JourneyFrame is upstream of UREEL.

## 7. Bubble / web layer role

Bubble, React, Next.js, and adjacent web layers may handle logic, authenticated interaction, forms, dashboards, content, state controls, route views, and administrative surfaces.

Their role is not diminished by UREEL. Their role becomes clearer: they provide accessible logic interfaces and structured state interaction while remaining downstream of server authorization and canonical proof.

HTML/web/Bubble may project interface state, but cannot own canonical state.

## 8. Unreal layer role

Unreal may render realm embodiment.

Its role is immersion, simulation, spatial presence, agent embodiment, environmental reaction, world interaction, and high-fidelity consequence. Unreal can make the realm feel entered rather than browsed.

Unreal may render immersion, simulation, and world interaction, but cannot bypass proof.

Unreal is not authorized to become the source of data truth, proof truth, identity truth, or sealed reality-state.

UWebBrowser is a possible bridge mechanism, not the whole system.

```text

```

UWebBrowser may allow web realm surfaces to be embedded inside Unreal. It may expose existing web logic and interface state inside an immersive shell. It may reduce duplication between web application logic and realm embodiment.

But UWebBrowser is not canonical truth.

It is a presentation bridge.

It does not replace:

- database truth

- AECHO continuity

## 10. Web-to-Unreal communication model

Web-to-Unreal communication must be explicit, constrained, inspectable, and downstream of authorized state.

The web layer may emit presentation events, interaction intents, projection state, selected JourneyFrame context, and non-secret display payloads. Unreal may respond by changing spatial state, visual state, agent behavior, camera focus, environmental atmosphere, or interaction affordances.

The communication model must never pass raw secrets into browser projection. It must never allow Unreal to write canonical proof directly. It must never allow embedded web state to outrank server authorization.

Bubble/web handles logic and state interaction.
Unreal renders realm embodiment.
UWebBrowser bridges them.
AuditEvent proves.
RealityEvent seals.
AECHO remembers.

## 11. User experience model: entering a world, not browsing a dashboard

The user enters UREEL as a reality field, not a dashboard skin.

A dashboard asks the user to scan panels.

UREEL asks the user to cross thresholds, witness consequence, complete proof loops, and perceive their JourneyFrame as an inhabited topology.

The user's actions should visibly alter the realm only when the action corresponds to proof, distinction, transmutation, or authorized state interaction. The experience model is not decoration over a CRUD app. It is a readable world projected from proof-backed state.

UREEL micro-interactions are not generic engagement loops.
