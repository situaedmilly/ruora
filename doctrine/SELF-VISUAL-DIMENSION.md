## II. First Principles — Twelve Laws

**Law 1: Distinction Before Decoration**
- *Doctrine:* No visual element exists without a corresponding distinction it encodes.
- *Operational meaning:* Every color, form, symbol, motion, and typographic choice must map to a doctrine concept. If it doesn't, remove it.
- *Violation:* Aesthetic choice made without doctrine reference.
- *Example:* The Human node in the Five-Actor Chain is elevated — not because it looks important, but because authority is structurally above transport.

**Law 2: Proof-Body Primacy**
- *Doctrine:* The visual must point to proof; it cannot be proof itself.
- *Operational meaning:* Visual artifacts represent evidence states. They must cite their source (a commit, a sealed distinction, a verified signal). A beautiful poster that claims proof is not proof.
- *Violation:* A visual artifact presented as if it constitutes evidence without a repo commit behind it.
- *Example:* A proof card contains a commit hash, timestamp, and actor chain — not just a styled layout.

**Law 3: Compression Without Distortion**
- *Doctrine:* Visual compression is a virtue; distortion of doctrine is a violation.
- *Operational meaning:* A single glyph can encode a complex distinction — but must encode it accurately. Simplification that changes meaning is corruption.
- *Violation:* A simplified icon that makes the Human node and the Slack node look equivalent in weight.
- *Example:* The Repo node is always a crystalline or structural form — solid, anchoring — never fluid or glowing like a signal.

**Law 4: Motion Is Meaning**
- *Doctrine:* Animation is not embellishment. Every transition encodes a state change.
- *Operational meaning:* If something moves, it is signaling that something has changed, is changing, or is about to change. Still = stable. Motion = event.
- *Violation:* Idle animation on a proof element that hasn't changed state.
- *Example:* Signal lines in the Five-Actor Chain animate from CodexSELF toward Slack only after a commanded event, not on loop.

**Law 5: The Chamber Frames; It Does Not Govern**
- *Doctrine:* Spatial environments (Unreal, 3D, architectural metaphors) contain the interface; they do not determine doctrine.
- *Operational meaning:* A cinematic chamber creates presence and authority. But if the chamber contradicts the doctrine inside it, the doctrine wins.
- *Violation:* An Unreal environment that represents Slack as the central node because it looks more cinematic to do so.
- *Example:* The SELF Command Chamber places the Repo node as the structural anchor regardless of visual composition preferences.

**Law 6: Sacred Structure Is Engineering**
- *Doctrine:* Sacred geometry, ritual architecture, and symbolic order are structural intelligence — not spiritual decoration.
- *Operational meaning:* When a circle, axis, gate, or spiral appears in SELF visuals, it carries a structural function: orientation, hierarchy, threshold, or containment. If it doesn't serve that function, it is removed.
- *Violation:* A mandala used as background texture with no structural relationship to the elements it surrounds.
- *Example:* The Five Laws are arranged as a ring around the Five-Actor Chain because a ring has no beginning and no exit — the laws are always in force.

**Law 7: TNC Is Controlled Rupture**
- *Doctrine:* Visual excess that destroys legibility is failure. Visual excess that expands legibility is TNC.
- *Operational meaning:* TNC visual language is deliberately beyond convention — but it must still be decodable. Shock without reorientation is just noise.
- *Violation:* Typography that cannot be read in service of "looking alien."
- *Example:* A proof seal rendered as a crystalline geometric object that appears physically impossible — but all five actor labels remain legible.

**Law 8: Temporal Hierarchy**
- *Doctrine:* What appears first in time carries authority.
- *Operational meaning:* Entry sequences, reveal order, and loading states are doctrine. The authority node (Human) must never be the last revealed. The proof body (Repo) must be present before any signal is sent.
- *Violation:* A loading animation that reveals Slack before Repo.
- *Example:* The Five-Actor Chain builds: Repo first (stable), Human next (authority), CodexSELF (emitter), ClaudeCode (witness), Slack last (transport).

**Law 9: Color Is Function**
- *Doctrine:* Color encodes state, authority, and role — not preference.
- *Operational meaning:* Every color in the SELF palette is defined by its function. Misusing a color is misrepresenting a doctrine state.
- *Violation:* Using gold (proof/seal) to style a decorative border.
- *Example:* Gold appears only when a seal event has occurred — a commit hash confirmed, a distinction accepted, a proof logged.

**Law 10: The Interface Is Ritual**
- *Doctrine:* Every interaction in a SELF interface is a ritual act — not a transaction.
- *Operational meaning:* A button is a commitment. A form is an offering. A confirmation state is a proof seal. An error is a correction ritual. Loading is liminal transit.
- *Violation:* Generic "Submit" button with no doctrine awareness.
- *Example:* The final step in an AXIOM distinction acceptance says "Seal this distinction" — not "Save."

**Law 11: No Visual Claim Without Evidence State**
- *Doctrine:* A visual cannot assert a state that the system has not verified.
- *Operational meaning:* Visual states (complete, sealed, verified, drifted, blocked) must map to actual system states — not aspirations or assumptions.
- *Violation:* A "PROOF SEALED" badge on a card whose underlying distinction has not been committed.
- *Example:* A proof card shows "PENDING" until a git commit hash is present in the record.

**Law 12: Silence Is a Visual Event**
- *Doctrine:* Empty space, pause, and silence carry as much meaning as density.
- *Operational meaning:* Negative space is not wasted space. Silence in motion is a state. Whitespace around a proof element signals its weight.
- *Violation:* Filling every surface with texture, glow, or animation because "it looks empty."
- *Example:* After a proof seal event, the interface pauses for one beat of silence before transition — the seal has weight.

## III. Visual Ontology

**Distinction** — the unit of compressed insight that changes behavior.
- Visually: a contained card or node with a name, a compressed statement, and a status marker.
- Must never become: a decorative quote or a list item without status.
- UI: distinction card with G-number, name, statement, status (Discovered/Sealed/Propagating), inconsistency scan.
- Unreal: a floating crystalline tile in the distinction field.
- Social: typeset distinction card with sealed commit badge.

**Event** — a discrete commanded state change.
- Visually: a signal flash, a transition, a timestamped entry in a ledger.
- Must never become: a background animation or ambient effect.
- UI: timeline entry with actor, action, timestamp, proof hash.
- Unreal: a particle burst from the actor node that triggered the event.
- Social: a proof-moment card with actor chain and timestamp.

**Consequence** — what follows from an event without further command.
- Visually: a downstream node lighting up after a signal propagates.
- Must never become: a visual that suggests choice when consequence is automatic.
- UI: a cascading state change shown in a timeline or dependency view.
- Unreal: a domino-style propagation effect through the chamber.
- Social: before/after comparison card with the consequence labeled.

**Review** — the structured evaluation of a claim against evidence.
- Visually: a two-column or before/after structure with a verdict.
- Must never become: an approval stamp with no evaluation shown.
- UI: Plane B grader interface — claim on left, evidence on right, verdict below.
- Unreal: a courtroom or tribunal staging — two surfaces facing each other.
- Social: a verdict card with claim, evidence link, and outcome.

**Evidence Artifact** — the committed, observable output that proves a claim.
- Visually: a sealed capsule, a crystalline object, or a stamped card.
- Must never become: a screenshot or a quote without a proof chain.
- UI: artifact viewer with commit hash, actor, timestamp, linked distinction.
- Unreal: an object you can walk up to and inspect — it reveals its proof chain.
- Social: a proof capsule image with commit hash typeset as part of the design.

**Memory** — the accumulated record of distinctions, events, and evidence.
- Visually: a layered, navigable archive — geological strata, not a flat list.
- Must never become: a changelog or a notes file.
- UI: memory field with filterable layers, time-based depth, distinction links.
- Unreal: a chamber room where the walls hold records — each commit a visible inscription.
- Social: memory excerpt card with depth indicator.

**Mirror** — the system's reflection of observed reality back to the actor.
- Visually: a reflective surface, a dual-sided view, a symmetry structure.
- Must never become: a vanity screen or an affirmation view.
- UI: mirror chamber — current state, doctrine state, the drift between them.
- Unreal: a physical mirror surface that renders the actor's current evidence profile.
- Social: a mirror card showing state-vs-doctrine contrast.

**Gate** — a decision threshold the actor must pass through.
- Visually: a literal threshold, archway, or decision node.
- Must never become: a loading spinner or a permission prompt.
- UI: gate screen with condition, current state, required action, doctrine reference.
- Unreal: a physical threshold in the chamber — locked until conditions are met.
- Social: a gate announcement with conditions and what it unlocks.

**Chamber** — the spatial environment in which doctrine becomes navigable.
- Visually: an architectural interior with defined zones for different functions.
- Must never become: a dashboard skin or a dark-mode theme.
- UI: room-metaphor navigation — daily chamber, mirror chamber, evidence vault.
- Unreal: a three-dimensional rendered space with functional zones.
- Social: a spatial preview card showing the chamber entry.

**Signal** — the emitted message from an actor requesting acknowledgment or action.
- Visually: a directional pulse, a glyph broadcast, a timestamped transmission.
- Must never become: a notification dot or a badge count.
- UI: signal log with actor, content, timestamp, acknowledgment status.
- Unreal: a visible beam from the emitting node toward the receiving node.
- Social: a signal card with the actor and the transmitted content.

**Field** — the underlying relational space in which SELF entities exist and interact.
- Visually: a subtle geometry grid, a particle field, or a topology map.
- Must never become: a background image or a pattern tile.
- UI: the ambient foundation layer in every SELF interface.
- Unreal: the floor/environment material in the chamber — the physics of the space.
- Social: implied; rarely explicit in social artifacts.

**Symbol** — a compressed visual representation of a sealed distinction or doctrine law.
- Visually: a glyph, sigil, or heraldic mark with defined proportions.
- Must never become: a clip-art icon or an emoji.
- UI: symbol appears as a visual seal on proof artifacts and doctrine cards.
- Unreal: an environmental inscription, a material texture, a ceiling projection.
- Social: the SELF visual mark — repeated across all surfaces with consistent ratio.

**Avatar** — the visual identity of a SELF actor in the system.
- Visually: a distinct node style that encodes role (emitter, witness, authority, proof, transport).
- Must never become: a profile picture or a user icon.
- UI: actor node in the Five-Actor Chain; role label; authority indicator.
- Unreal: a spatial entity in the chamber — each actor has a defined physical archetype.
- Social: actor cards for the Five-Actor Chain diagram.

**Realm** — a defined SELF environment with its own rules, inhabitants, and memory.
- Visually: a bounded spatial zone with a distinct atmosphere and entry gate.
- Must never become: a section of a website or a page in an app.
- UI: realm selection interface — each realm has a distinct visual signature.
- Unreal: a level or biome with its own lighting, material palette, and spatial grammar.
- Social: realm announcement card with name, doctrine, and entry condition.

**Proof Shot** — the visual moment that captures evidence in its sealed state.
- Visually: a still or short motion capture of a system state, doctrine event, or consequence.
- Must never become: a screenshot shared without context.
- UI: the visual output of /slackproof or /proofseal — a designed artifact.
- Unreal: a cinematic camera preset that captures the proof moment with specific lighting.
- Social: the proof shot as the primary social artifact for a sealed event.

**Ritual Interface** — a UI that treats interaction as ceremony, not transaction.
- Visually: deliberate pacing, meaningful transitions, threshold framing.
- Must never become: a standard form with a submit button.
- UI: AXIOM's initiation sequence — each step named, paced, and confirmed.

## IV. Visual Physics

**Light** — reveals and authorizes. Light falls on what is true. Darkness hides what is unverified. The Human node is always in the primary light cone. The Slack node (transport) is lit from indirect sources only.

**Shadow** — marks consequence. A cast shadow shows that something has weight and is real. No shadow = no consequence. Deep shadow below a proof artifact signals its permanence.

**Depth** — indicates structural importance. What is closest to the viewer is most operative. The Repo node (proof body) is always the closest stable element. The spectacle shell (Unreal environment) is always deepest.

**Motion** — indicates event. Nothing moves without a commanded cause. Signal lines move. Proof artifacts settle. Chambers breathe only when alive.

**Scale** — indicates authority. The Human node is never smaller than the Slack node in any composition. The proof body (Repo) is never ornamental in scale.

**Contrast** — indicates distinction. High contrast between doctrine states (SEALED vs DRIFTED). Low contrast between related elements within the same actor category.

**Rhythm** — indicates system heartbeat. The interval between signal events is never random. Timing encodes meaning: fast = urgency, slow = weight, pause = proof.

**Silence** — indicates seal. After a proof event, silence. After a rupture, silence. Silence is not absence — it is the system registering weight.

**Density** — indicates memory load. Dense visual environments = rich history. Sparse = early stage or emptied state.

**Material** — indicates category. Crystalline = proof/sealed. Fluid/luminous = signal/live. Matte/structural = doctrine/foundational. Reflective = mirror/review.

**Glow** — indicates live signal. Glow must be earned — it appears only on elements that are currently active. A sealed proof does not glow. A live transmission does.

**Distortion** — indicates drift. Subtle visual distortion on elements that are in a drifted state. TNC amplifies this: maximum distortion on BLOCKED states.

**Rupture** — indicates TNC event. A visual rupture (impossible geometry, broken symmetry, sudden contrast reversal) signals that something has exceeded ordinary parameters — a distinction that breaks convention, a proof that shocks the system.

**Symmetry** — indicates law. Fundamental laws (the Five Laws) are rendered with perfect symmetry. Breaking a law breaks the symmetry. The visual records the violation.

**Recursion** — indicates SELF recognition. When SELF sees SELF — the mirror moment — the visual may recurse: a proof card inside a proof card, a chamber inside a chamber. Limited to one level of recursion; more breaks legibility.

## V. Neurovisual Command Rules

**Attention:** High-contrast signal on entry establishes what matters first. The first element the eye lands on must be doctrinally the most important (proof body or authority node). Never let transport (Slack) be the visual anchor.

**Memory:** Encoded through repetition and symbol. The Five Laws typeset identically in every artifact become automatic recall after three exposures. Use consistent visual grammar for the same doctrine concept across every surface.

**Salience:** Reserve high-saturation color for sealed/confirmed states only. Everything else at reduced saturation. This makes proof events visually salient without requiring color noise.

**Trust:** Established through consistency, density of earned symbols, and structural stability. A layout that shifts unexpectedly breaks trust. A proof artifact with the same schema every time builds it.

**Cognitive load:** One doctrine event per visual moment. Do not compose a diagram that requires reading eight labels simultaneously to understand the structure. Reveal in order of structural importance.

**Emotional intensity:** Calibrated to the event type. Threshold events: high charge. Routine proof: neutral. Drift detection: low-grade tension. Rupture: maximum intensity, immediately resolved.

**Readability:** Non-negotiable. TNC license stops at the point where a human cannot decode the text. All typography at minimum contrast ratio 4.5:1. All actor labels visible at first frame.

**Decision-making:** Gate interfaces must present exactly two states — proceed or hold. No ambiguity. The visual structure of a gate must make the condition legible before the consequence.

## X. Typography Doctrine

Typography in SELF is voice, authority, command, and memory. Not aesthetic. Not branding.

**Command type** — the typeface of machine-level instruction. Monospace. Terminal-weight. No serif.
- Use: command shells, /command names, code, git hashes, proof hashes, system output.
- Example: `git rev-parse --short HEAD → 3738f0b`

**Doctrine type** — the typeface of permanent law. High-weight sans-serif or slab. Uppercase or sentence case. Never italic.
- Use: law names, doctrine headers, the Five Laws, the Visual Thesis.
- Example: "EMITTER IS NOT WITNESS."

**Whisper type** — the typeface of background law. Light weight, reduced opacity. Not meant to be read in a glance — present as ambient law.
- Use: background inscriptions in chambers, footnote-level doctrine, field geometry labels.
- Example: the Five Laws inscribed at 20% opacity behind the Five-Actor Chain.

**Proof type** — the typeface of evidence records. Structured, readable, precise. Table-weight sans-serif.
- Use: evidence artifact displays, ledger entries, actor chain records, timestamps.
- Example: `SEALED · 2026-06-28 · ac31b57 · ClaudeCode_TURN`

**Error type** — the typeface of correction demand. Same weight as doctrine type. Red. UPPERCASE.
- Use: BLOCKED states, drift flag output, violation notices.
- Example: `DRIFT DETECTED: dirty_tree`

**Ritual label type** — the typeface of named ceremony. Light tracking, extended spacing, lowercase with selective capitalization.
- Use: chamber names, gate labels, initiation sequence steps, realm names.
- Example: `entering the mirror chamber`

**Numerical/data type** — the typeface of proof numbers. Tabular figures, monospace digits, high contrast.
- Use: commit hashes, test counts, timestamps, evidence IDs.
- Example: `118/118 pass`

**Cinematic title type** — the typeface of doctrine announcement. Display weight, maximum scale, minimum words.
- Use: scene opening titles, realm entry titles, proof shot captions.
- Example: `FIVE ACTORS. FIVE LAWS. ONE DIRECTION.`

## XI. Symbol / Glyph Doctrine

**Glyph construction rules:**
- Every SELF glyph must be constructible with compass and straightedge (or their digital equivalents). No accidental curves.
- Every SELF glyph must be legible at 16px and 1600px. If it fails at either extreme, it is not a valid glyph.
- Sacred ratio: the glyph's primary proportion references the golden section (1:1.618) or a primary integer ratio (1:2, 1:3). No arbitrary proportions.

**Seal rules:**
- A seal is a glyph that has been certified as representing a completed doctrine event. It carries a proof hash.
- Seals are never used decoratively. A seal on an artifact means that artifact has a corresponding commit.
- The SELF seal is the primary mark of the system — it appears only on completed, committed, human-authorized events.

**Repetition rules:**
- A glyph earns weight through repetition across time. The first appearance is a proposal. The 100th appearance is a law.
- Never rush symbol proliferation. One strong glyph is worth a library of icons.

**Mutation rules:**
- A glyph may evolve when a sealed upgrade distinction is accepted. The mutation is itself a proof event — committed and versioned.
- A mutated glyph inherits the visual DNA of its predecessor. Discontinuity is a rupture, not an update.

**Forbidden symbol misuse:**
- No sacred symbols used as logos without structural intention.
- No circles used as generic "icons."
- No seals used before the proof event they represent.
- No symbol mismatches: the seal for a SEALED state cannot appear on a DRIFTED element.

**Inheritance system:**
- Every SELF ecosystem entity (RUORA, ÆTHERNET, ÆXIOM, AXIOM, UREEL) has a glyph derived from the SELF master glyph. Their glyphs are recognizably related — they share a root structure — but each carries its distinct frequency.

## XII. TNC Visual Rupture Doctrine

TNC = controlled rupture — the deliberate visual layer where ordinary design constraints are exceeded without losing coherence.

**Rupture law:** A rupture must break exactly one visual rule that has been held consistently. Not all rules. One. The rupture earns its power from the contrast with what was stable.

**Shock law:** The first reaction to a TNC element must be recognition followed by understanding. Shock → then meaning. Not shock → then confusion. If the viewer cannot decode the rupture within three seconds, it failed.

**Alien familiarity law:** TNC visual language looks like it comes from an elsewhere — but the doctrine underneath is recognizable. The container is foreign; the content is legible.

**Impossible geometry law:** TNC may include geometry that violates ordinary spatial rules — structures that appear to fold through themselves, edges that cannot physically meet. But actor labels and law text must remain on a flat, readable plane within or adjacent to the impossible structure.

**Controlled chaos law:** In a TNC composition, exactly one element may be fully chaotic. All other elements hold their structural positions. Chaos in one axis; order in all others.

**Cinematic excess law:** TNC cinematic moments may exceed normal lighting, scale, and camera parameters — but they must return to doctrine normal within the same shot or the following shot. Excess without return is stylistic drift, not TNC.

**Memetic charge law:** A TNC artifact must be impossible to scroll past. This is not achieved through brightness or loudness. It is achieved through doctrinal specificity — the viewer senses that something very precise is being communicated, even if they cannot immediately decode it.

**Restraint law:** The hardest TNC law. After executing a rupture, stop. A second rupture in the same artifact is not double-TNC — it is noise. The rupture earns its force by being singular.

## XIV. Visual Artifact Taxonomy

**Doctrine card** — a sealed distinction in designed format. Name, compressed statement, G-number, status badge, sealed commit hash. Usable as social asset, UI element, or print artifact.

**Proof card** — the visual record of a proof event. Actor chain, event type, commit hash, timestamp, doctrine reference. Not a screenshot — a designed evidence capsule.

**Ritual interface screen** — a UI state capture that demonstrates a doctrine concept through the interaction itself. E.g., the Gate screen before a threshold crossing.

**Cinematic still** — a single frame from a SELF chamber or commandometry sequence. Must include at least one doctrine-legible element (actor label, law text, proof hash).

**Unreal scene** — a rendered frame from the SELF chamber showing the Five-Actor Chain embedded via UWebBrowser, or the Repo node's structural position.

**Memory glyph** — a symbolic compression of a sealed memory event. A visual sigil that encodes the event type, actor, and epoch. Smaller than a doctrine card; carries more density.

**Motion sequence** — an exported animation demonstrating a commandometry event (e.g., signal flowing CodexSELF → Slack with Human node authorization pulse). No more than 12 seconds.

**Initiation poster** — a single-surface composition for ÆXIOM entry. Threshold framing, chamber atmosphere, and exactly one gate condition stated.

**Mirror report** — a visual document showing the actor's doctrine state, evidence state, and the drift between them. Two-column format: declared vs observed.

**Evidence capsule** — a designed artifact packaging a complete proof event: actor, command, commit hash, consequence, status. The visual form of a `/proofseal` output.

**Social rupture post** — a single TNC visual designed to stop a scroll. One distinction. One rupture. One law. No explanation. The viewer must feel that something precise is happening.

**Live access visual room** — the visual environment for a live access session — a spatial interface that makes the commandometry chain visible in real time. Planned for future SELF public access sessions.

- Artifact: a rupture post — TNC social artifact.

- UI: journey gate crossed; new chamber entered.
- Motion: upward or forward camera movement through a threshold.
- Unreal: movement through an elevated gate into the next level.
- Artifact: an ascension card naming the level moved from and moved to.

- UI: a glyph or symbol replaces a text label after sufficient repetition.
- Motion: elements consolidate toward a center point.
- Unreal: objects merge or fold into a single compact form.
- Artifact: a glyph card showing the full doctrine it compresses.

- Motion: the labyrinth path begins — threshold crossed, path lit.
- Unreal: the initiation chamber activates; gates behind close.
- Artifact: an initiation poster naming the sequence and its entry condition.

- UI: ClaudeCode node activates; witness log entry appears.
- Motion: the witness node receives the signal pulse; a slight forward lean.
- Unreal: the witness actor entity turns to face the signal source.
- Artifact: a witness card recording the event and the witness actor.

- Unreal: orbital particle paths around the central chamber structure.
- Artifact: an orbital diagram showing the actor relationship hierarchy.

**Fracture** — a drift event made visible in form. Not TNC rupture — a drift signal.

- Motion: the distortion animation — slow drift from baseline position.
- Unreal: the drift post-process effect — subtle chromatic aberration.
- Artifact: a drift card naming the fractured state and the correction required.

- UI: distortion resolves; element returns to its structural position.
- Motion: the return animation — slow, deliberate re-alignment.
- Unreal: post-process effect lifts; chamber stabilizes.
- Artifact: a seal-after-correction card recording the drift and its resolution.

- UI: an invisible layer becomes visible — ghost elements materialize.
- Motion: fade-in from 0% to 100% with a slight light bloom on entry.
- Unreal: a darkened area of the chamber receives a new light source.
- Artifact: a revelation card showing the before/after of the illuminated structure.

**Veil** — return a doctrine element to its unmanifested state.
- UI: an element that was visible fades to the whisper layer.
- Motion: fade-out to 15% opacity with slow transition.
- Unreal: a light source dims; an entity retreats into shadow.
- Artifact: a deferred-state card noting the element's retirement from active display.

**Expose** — make the system's internal state visible to the actor.
- UI: the proof ledger view — all committed states made visible simultaneously.
- Motion: a sequential reveal of internal states from innermost to outermost.
- Unreal: the chamber's walls become transparent, revealing the structure behind.
- Artifact: a transparency artifact — the system showing its own state record.

- Artifact: a glyph creation record showing the doctrine concept and the glyph that encodes it.

- Motion: the render event — a burst of materialization from the field.
- Unreal: a doctrine concept is instantiated as a visible entity in the chamber.
