## 1. Purpose

This pass reconciles five doctrine-linked PDFs against the canonical RUORA / SELF ontology.

The reconciliation identifies one critical drift family:

> Several documents elevate "control plane," "reconciler," "controller," "target vector," or declared ontology into the authoring rank of SELF.

This is invalid.

The correction is not to discard control theory, Kubernetes metaphors, reconciliation loops, semantic alignment layers, or runtime-controller language. These are useful subordinate mechanics.

The correction is to restore rank:

```text
Doctrine / SELFControl
        ↓
Observed State Primacy
        ↓
Reality Classification
        ↓
Controller / Reconciler / Runtime Machinery
        ↓
Mutation
        ↓
Proof
        ↓
Seal
```

A controller may reconcile system state.

It may not author SELF.

A target may express doctrine-derived intent.

It may not outrank observed reality.

A declared ontology may guide interpretation.

It may not become the first witness.

## 2. Canonical Ruling

### 2.1 SELF is not a control plane

SELF is the identity-intelligence core.

SELF converts observed behavior into self-knowledge through evidence-bound reflection, pressure, classification, and agency-return.

SELFControl is not equivalent to a Kubernetes controller, reconciler loop, runtime operator, automation layer, orchestration stack, or target-state engine.

Control-plane metaphors are permitted only as subordinate implementation analogies.

They are forbidden as ontological definitions of SELF.

### 2.2 Controllers are below SELFControl

A controller is an execution mechanism.

A reconciler is an execution mechanism.

A control loop is an execution mechanism.

A runtime automation is an execution mechanism.

All execution mechanisms must be subordinated to:

1. doctrine
2. observed-state primacy
3. reality classification
4. execution-class firewall
5. proof
6. seal

Any document that places controller logic above doctrine is drifting.

Any document that makes reconciler logic the author of SELF is drifting.

Any document that makes target-state convergence more authoritative than observed-state evidence is drifting.

## 3. Observed State Primacy

### 3.1 First Witness Law

Observed state is the first witness.

Declared doctrine, desired target, ontology asset, language pack, roadmap, internal belief, symbolic reading, or system intention may not supersede directly observed state.

The correct sequence is:

```text
Inspect observed state
→ compare against doctrine
→ classify evidence tier
→ identify divergence
→ apply pressure
→ produce correction
→ prove correction
→ seal only after proof
```

The incorrect sequence is:

```text
Declare target
→ assume target is truth
→ reconcile runtime toward declaration
→ mutate without witness
→ treat convergence as proof
```

The second sequence is forbidden.

### 3.2 Target Vector Demotion

A Target Vector is a doctrine-derived declaration.

It is not truth.

It is not proof.

It is not observed state.

It is a provisional orientation that must be tested against evidence.

A Target Vector may guide reconciliation only after:

- live state is inspected
- evidence tier is assigned
- divergence is classified
- mutation class is authorized
- proof conditions are defined

If a Target Vector conflicts with observed state, the system must freeze mutation and reconcile.

### 4.1 Valid Use of Control Theory

Control theory may strengthen doctrine when it is used to formalize:

- feedback loops
- divergence detection
- stability conditions
- contraction toward verified correction
- quantitative proof requirements
- Bayesian identity updates
- runtime drift detection
- post-mutation validation

### 4.2 Invalid Use of Control Theory

Control theory becomes drift when it:

- defines SELF as a controller
- defines OURSELF as a control plane
- treats Kubernetes architecture as the source model of identity
- elevates target state above observed state
- allows reconcile loops without freeze gates
- acts without proof
- seals without verification
- reconciles toward false targets instead of refusing them

## 5. Negate Primitive Restoration

The TNC spine requires three movements:

```text
Trap
Negate
Continue
```

Several drifting documents preserve Trap and Continue while weakening or omitting Negate.

This is invalid.

Without Negate, the system may reconcile toward false targets, aestheticized errors, or doctrine-shaped fantasies.

### 5.1 Negate Definition

Negate is the refusal function.

It rejects:

- false targets
- unsupported declarations
- rank inversions
- surveillance logic
- dependency-producing outputs
- symbolic claims presented as fact
- speculative claims presented as Verified
- automation paths without proof
- mutation requests outside authorized execution class

### 5.2 Required Negate Gate

Before any reconcile, plan, mutate, automate, publish, or seal action, agents must ask:

> What must be refused before anything is continued?

If the answer includes a rank violation, unsupported claim, missing witness, unsafe execution path, or unclassified evidence tier, mutation freezes.

## 6. Freeze-and-Reconcile Gate

A freeze gate is mandatory when any of the following are detected:

1. controller elevated above SELFControl
2. declared target elevated above observed state
3. ontology declaration treated as witness
4. Verified claim lacks direct evidence
5. symbolic or speculative claim is presented as fact
6. public/private ontology vocabulary diverges
7. Mirror or Forge is demoted into chat furniture
8. Slack, Notion, OAuth, webhook, Zapier, Make, SDK, or remote automation is treated as routine without firewall
9. `action.execute` fires by default
10. seal is attempted without proof

### 6.1 Freeze Behavior

During freeze:

- do not mutate
- do not publish
- do not push
- do not automate
- do not execute remote actions
- do not update public doctrine
- do not treat desired state as current state

The only authorized action is reconciliation.

### 6.2 Reconciliation Output

A valid reconciliation output must include:

- drift statement
- violated doctrine
- evidence tier
- corrected hierarchy
- refused path
- authorized next action
- proof requirement
- rollback path

## 10. Reality Classification Enforcement

All doctrine claims must preserve tier separation.

**Required Tiers**

| Tier | Definition |
|---|---|
| Verified | Direct evidence, observed state, file content, inspected runtime, or explicit user-provided material |
| Probable | Supported inference, not directly proven |
| Unwitnessed | Asserted but not inspected |
| Symbolic | Metaphor, archetype, alchemical or spiritual framing |
| Speculative | Possible but unsupported |

**Non-Negotiable Rule**

Never present speculation as fact.

Never present symbolic language as verified reality.

Never present declared targets as observed state.

Never present unwitnessed runtime as Verified.

## 11. Seal Rule

Seal is terminal.

Seal cannot occur merely because a document is elegant, coherent, intense, aligned in tone, or doctrine-shaped.

Seal requires proof.

**Required Seal Sequence**

```text
Inspect
→ Compare
→ Classify
→ Negate false path
→ Apply authorized correction
→ Prove
→ Seal
```

**Invalid Seal Sequence**

```text
Declare
→ Reconcile
→ Execute
→ Assume aligned
→ Seal
```

Seal without proof is drift.
