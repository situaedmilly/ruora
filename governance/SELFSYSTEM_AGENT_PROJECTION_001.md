## 0. Reality Shift

The observed shift is not that one model became more reliable.

The observed shift is that a parent execution lane can instantiate a separate
model execution context, bind that context to a named SELFSYSTEM role and
authority, receive its result, then route the disposition without performing the
subordinate computation itself.

This creates a new architectural primitive:

```
SELFSYSTEM identity
  + authority contract
  + context boundary
  + source binding
  + task
  -> isolated compute projection
  -> disposition
```

The projection is technical and executable. It is not evidence of separate
consciousness. It is a governed computational locus.

```

  != COMPUTATION
```

## 4. AgentProjection Contract

Before any SELFSYSTEM identity is executed through a child context, the parent
or bridge must instantiate an `AgentProjection`.

```
AgentProjection
  projection_id
  selfsystem_id
  projection_type
  parent_execution_id
  child_execution_id
  issued_by
  issued_at
  execution_substrate
  context_policy
  task
  source_bindings[]
  authority
  forbidden_actions[]
  independence_requirements
  memory_policy
  tool_policy
  mutation_policy
  output_contract
  validation_contract
  lifecycle_state
  unresolved_dimensions[]
```

This is a semantic contract, not a schema.

No downstream operation receives only a raw role label such as `HBCSELF`. It
receives an `AgentProjection` or it fails closed.

## 5. Projection Lifecycle

```
PROJECTION_REQUESTED
  -> ALCHEMISELF_RESOLVED
  -> PROJECTION_BOUND
  -> CHILD_CONTEXT_CREATED
  -> SOURCE_BINDINGS_VERIFIED
  -> COMPUTATION_RUNNING
  -> OUTPUT_RETURNED
  -> OUTPUT_VALIDATED
  -> CHILD_CONTEXT_CLOSED
  -> DISPOSITION_ROUTED
```

If any lifecycle step is unresolved, the projection may not be treated as a
valid SELFSYSTEM disposition.

The parent may orchestrate, but it may not silently rewrite the child's findings
into a stronger or weaker result.

## 6. Identity and Authority Rules

1. A child may report the projection it was given.
2. A child may not self-mint SELFSYSTEM identity.
3. A child may not expand its authority beyond the projection.
4. A parent may not expand the child's authority after output receipt.
5. A review-only projection may not repair, stage, commit, push, ratify, seal,
   generate, deploy, or open genesis.
6. A proof-only projection may not mutate the subject it proves unless the
   projection explicitly grants mutation authority.
7. A mutation projection may not review, pass, seal, or ratify its own result.
8. `AUTHOR_SELF != REVIEW_SELF` remains mandatory for hostile review.

Correct output identity form:

```
PROJECTION: HBCSELF@<projection_id>
AUTHORITY: REVIEW_ONLY
DISPOSITION: <verdict>
```

Incorrect output identity form:

```
I am HBCSELF, therefore this review has HBCSELF authority.
```

## 7. Context Boundary Rules

Context policy is part of projection authority.

```
FORKED_CONTEXT
  != NON_FORKED_CONTEXT
  != MEMORY_INHERITED_CONTEXT
  != MEMORY_ISOLATED_CONTEXT
  != SUBSTRATE_INDEPENDENT_CONTEXT
```

A non-forked child context can support session separation. It does not prove
model independence, identity authority, or absence of all contamination.

Model independence must be reported as one of:

```
MODEL_INDEPENDENT_YES
MODEL_INDEPENDENT_NO
MODEL_INDEPENDENT_UNRESOLVED
```

When runtime metadata does not expose the model boundary, the only lawful value
is `MODEL_INDEPENDENT_UNRESOLVED`.
