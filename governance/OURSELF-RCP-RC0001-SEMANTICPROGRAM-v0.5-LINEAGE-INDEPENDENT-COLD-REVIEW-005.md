### 2.2 `CR5-B01` — completeness fails, with one construction per element class — **BLOCKING**

**Class `begin`.** SP-019 was amended *in this revision* (CR4-09) to add "the originating DaySlot ordinal of the open active interval, while one is open" as an L-fact. SP-075 obliges an active interval to retain it; SP-053 lists "origin DaySlots" among the L-facts a DaySlot boundary preserves. The element that establishes that L-fact is `begin`.

> **Embodiment B′.** Substrate carries a single "current day" field and cannot record which DaySlot an interval originated in. It enters `active`, preserves every durable Entry, creates no Entry, emits an accepted outcome, is atomic, and is distinguishable from a no-op.

B′ honors SP-030, SP-031 (vacuously — no refusal), SP-037 and SP-038 — every requirement `begin`'s row invokes. Its failed-requirement set at `begin` is **empty**. SP-169's non-emptiness clause and SP-150 therefore compel `ADMITTED`. B′ has lost SP-075 and an SP-019 member, and no element in the presented sequence carries a clause identity naming that loss. Against a full embodiment W presented `⟨begin, record("A"), ⟨DaySlot boundary⟩, complete⟩` — SP-019's own worked example — B′ and W emit identical dispositions and identical failed-requirement sets.

Also absent from `begin`'s row: SP-160 (result determination), SP-163 (the authored edge mapping), SP-040, SP-042.

**Class `record`.** The row omits SP-071 (every admitted invocation receives exactly one admission ordinal at admission, before any transition evaluation), SP-044 (pending order equals accepted-record admission order), SP-045 (canonical order is total, stable across every contemplated discontinuity, and independent of wall-clock timestamps), SP-073, SP-082, SP-083, SP-043 and SP-160.

> **Embodiment C′.** Substrate orders by wall-clock timestamp and cannot produce a total order when two admissions share a timestamp — SP-045 and SP-070 falsified.

C′ can create the ordered pending contribution (SP-022 ✓), append it (SP-032 ✓), give it Entry identity (SP-021 ✓), and satisfy SP-024's comparator *description* for any run in which no timestamp collision occurs. On a run where one does, it fails SP-045 — invoked nowhere. Its failed-requirement set is empty; SP-150 compels `ADMITTED`; the divergence surfaces later as an ordering difference attributed to no capability decision at all. P-L1-A seals "+ canonical ordering"; P-L1-C's Fail list carries "ordering". This is the exact loss class CR-003 §3.5 was built around, re-entering through omission rather than through vocabulary.

**Class `complete`.** The row omits SP-025 (a completed Entry is immutable: no admitted operation deletes it, rewrites its content, changes its status, or replaces its canonical position), SP-044 (complete preserves relative order when the corresponding Entries join history), SP-049, SP-174 (what survives a restart: content, status, relative order).

> **Embodiment D′.** Substrate is a log-structured store with compaction that can rewrite a completed Entry's stored content under memory pressure — SP-025 falsified.

At `complete`, D′ creates exactly one durable Entry per pending contribution with correct content and status at the moment of the transition (SP-034, SP-020, SP-021, SP-024, SP-035, SP-037, SP-038 all ✓). Failed-requirement set empty → `ADMITTED`. SP-025's obligation is engaged by no element in SP-168's table, so an embodiment structurally incapable of honoring immutability is never required to declare it.

**Class discontinuity boundary.** The row is `n/a for failure`: "SP-156 makes `ADMITTED` the only lawful disposition, so a boundary's failed-requirement set is necessarily empty. An embodiment that cannot honor these does not dispose the boundary; it **fails RC-0001**."

> **Embodiment R′.** Re-enters the same logical Ledger identity after a restart with completed Entries intact, but cannot preserve **pending contributions** across the restart — SP-050 lists pending contributions among the L-facts that survive, and permits no degradation.

Present FT-03's trace `⟨begin, record("A"), restart, complete⟩`. SP-156 compels R′ to dispose the boundary `ADMITTED`. At `complete`, R′ has no pending contribution, so SP-160 step 2 yields `NO_RECORDED_CONTENT`; W yields an accepted complete. SP-152 detects an **outcome** divergence at index 4. It does not detect a **typed capability loss** anywhere, and it localizes the divergence at `complete` rather than at the boundary where the loss occurred. P-L1-B constitutional law 3 requires capability loss to be *typed* and explicit. Here it is neither typed nor localized — the condition v0.4 diagnosed in v0.3 as "explicit, and stopped short of typed."

The boundary row is therefore **inert in both directions**: its six named requirements can never be members of a failed set, and every capability failure at a discontinuity is structurally untypeable.

**Disposition of `CR5-B01` under the mandate's rule.** Every omitted requirement is already a published normative clause of this document and already a member of SP-167's set. I did not invent the missing rows and do not name what they should contain.

### 2.3 `CR5-01` — exactness fails: the published table contradicts SP-168's own definition — **MATERIAL**

SP-168: "Each presented element **invokes** a determinate set of semantic requirements: exactly those whose obligation is engaged by that element **at that presented index**. The invoked set is a function of the element **and the presented-sequence prefix**."

§2.0.1 publishes a function of **element alone**. There is no index parameter and no prefix parameter anywhere in the table.

The two are not reconcilable. Concretely, present `record("A")` at `state = idle`. SP-160 step 1 fires — the operation is not state-legal — and evaluation stops before content is examined. At that index:

- **not engaged:** SP-032's success clause (there is no success), SP-022 (no contribution is created), SP-021 (no Entry identity arises), SP-024 (no canonical position is assigned), SP-162 (SP-160 step 2 is never reached; content conditions are "evaluated **only if** the operation is state-legal");
- **engaged:** SP-033, SP-160, SP-043, SP-037, SP-038.

The table names all five non-engaged clauses anyway. It is over-broad by five at that index, and symmetrically over-broad at every successful `begin` (SP-031 is the refusal law and is not engaged) and every refused `begin` (SP-030's success consequences are not engaged).

**Why over-breadth is not harmless.** SP-169's minimality forbids naming a requirement the embodiment *can* honor. Whether an embodiment "can honor" an obligation that is *vacuously satisfied because a prior condition failed* is **defined by no clause**. Under the vacuity reading, C′ above cannot name SP-045 at any element; under the non-vacuity reading, an embodiment that cannot in general honor SP-022 may name `{SP-022}` at a state-illegal `record` — because §2.0.1 says that element invokes SP-022 — thereby converting a refusal into a capability disposition. A disposed element never reaches SP-160 (SP-153), and SP-043 counts only elements whose SP-160 result is `INVALID_TRANSITION`. So `illegal_transition_count` — one of the founder's six acceptance values — becomes embodiment-selectable. That is the CR3-07 defect class (two embodiments differing on a founder acceptance predicate with no clause violated) re-entering through the new invocation table.

I record the exploit as *arguable* rather than as an established escape, because the vacuity reading blocks it. The **determinacy defect is established either way**: SP-169's two-sided exactness test is stated over a predicate — "cannot honor" — that no clause defines over vacuously-satisfied obligations, and the two admissible readings yield different failed-requirement sets for the same substrate.

### 2.4 `CR5-02` — SP-167's closure predicate is a dangling reference — **MATERIAL**

> **SP-167:** "The requirement set is therefore the set of normative SP clauses inside this document's **SP-006 envelope**: closed, enumerated, and fixed at this candidate's digest."

**`SP-006` does not exist.** Zero occurrences in v0.5 outside SP-167's own sentence; zero occurrences in v0.4; zero in v0.3. The clause set runs SP-001…SP-005, SP-010, SP-011, SP-013…

SP-167 is the clause that makes the entire `CR4-01` repair possible: SP-169 states that "the only admissible names are clause identities," SP-168 states the table is "computed from this document by any reader," and SP-170 states that "clause identities do not merge." All three presuppose a determinate set boundary. That boundary is fixed by a reference that does not resolve.

The intended reading is recoverable by inference — §0.4 ("Only **SP** rows are normative") and the auditor's §0→§17 envelope both yield the same 111 rows — which is why this is MATERIAL rather than BLOCKING. But a normative set defined as "closed and enumerated" by a citation to a nonexistent clause is not closed by the document; it is closed by the reader's charity.

### 2.5 `CR5-03` — the flagship demonstration is non-exact under SP-169 — **MATERIAL**

§2.0, FT-13, FT-16 (CR4-01) and §18 all publish:

```
G′  failed-requirement set = { SP-022 }
H′  failed-requirement set = { SP-024 }
```

SP-032 is in `record`'s invoked set and reads: "success **appends one pending contribution in admission order**, leaves state active and durable Entries unchanged, and emits an accepted record outcome."

G′ "cannot hold a second pending contribution." It therefore cannot append the pending contribution. **It cannot honor SP-032.** SP-169's maximality — "every invoked requirement it cannot honor is named" — makes `{SP-022}` a nonconforming record. G′'s exact set is at least `{SP-022, SP-032}`.

H′ "can hold two but cannot preserve their canonical order." SP-022 requires "an observable **ordered** pending contribution"; SP-032 requires the append be "**in admission order**". **H′ cannot honor either.** H′'s exact set is at least `{SP-022, SP-024, SP-032}`.

The divergence at presented index 3 survives — the sets still differ — so the demonstration's *conclusion* holds. Its *computation* violates the clause it is offered as evidence for. And FT-16 (CR4-01)'s reasoning is wrong on its own text: it declares H′'s naming of `{SP-022}` nonconforming "because SP-022's obligation is one H′ genuinely meets." H′ does not meet SP-022; SP-022 requires order.

This is the same class of defect as CR4-01 itself: a repair whose worked example is not derivable from the clauses it cites.

## 3. Clause-identity calibration — both failure modes tested

The repair's thesis: `loss identity = identity of the semantic requirement(s) not satisfied`. The calibration standard: **distinguish every difference RC-0001 cares about, and refuse to distinguish differences it does not.**

### 3.1 `CR5-B02` — collision test SUCCEEDS: materially different failures, identical clause-identity set — **BLOCKING**

SP-170 asserts: "two embodiments failing different semantic requirements necessarily carry different failed-requirement sets, **because the requirements are the distinctions**. There is no coarser admissible name under which two distinct failures could collapse, since every admissible name is a clause identity and clause identities do not merge."

**The inference is a non sequitur.** That clause *identities* do not merge does not entail that distinct substrate failures map to distinct clause sets. It entails only that no *third*, coarser name exists. Two failures can fail the *same* clause. Whether they do is a function of clause **granularity**, and clause granularity is authored by this document — not fixed by any source.

**Construction 1 — SP-020, four obligations under one identity.**

> **SP-020:** "After a successful complete, each successful record in that active interval corresponds to **exactly one** **durable** Entry whose **content equals the recorded content** and whose **status is complete**."

> **Embodiment U′.** Fixed-width content column; truncates recorded content beyond 32 characters. Creates exactly one durable Entry, correct status, correct order.
> **Embodiment V′.** Exact content, exact status, exactly one Entry per contribution — but the store is in-memory and the Entry is not durable.

At `complete`, both fail SP-020 and nothing else in the row (SP-034, SP-021, SP-024, SP-035, SP-037, SP-038 all honored by both). Both publish `CAPABILITY_UNSUPPORTED(complete)` with failed-requirement set **`{SP-020}`**. Because a disposed element never reaches transition law (SP-150, SP-153), neither produces Entries; state remains `active` and pending intact for both. **U′ and V′ agree on every disposition, every failed-requirement set, and every admitted element's outcome. They compare fully conforming to each other under SP-152.**

Their losses are not the same fact. V′ loses durability — a P-L1-A sealed scope member ("+ durability") and a P-L1-C Fail-list member ("durable state"). U′ loses content fidelity — the founder's acceptance predicate `entries[0].content = "Reflect"`. This is CR-003 §3.5's structure exactly, relocated from a coarse self-chosen label to a coarse authored clause.

**Construction 2 — SP-037, one obligation, materially different failures.**

> **Embodiment P′.** Non-transactional store; an observation can catch `complete` with half the Entries materialized.
> **Embodiment Q′.** Materializes Entries atomically but cannot atomically clear the pending projection while changing state; an observation can see `state = complete` with pending still present.

Both fail SP-037 and only SP-037. Both publish `{SP-037}`. Both compare equal. P′ exposes a partial Entry set; Q′ exposes a stale L-fact of a different SP-019 member.

**Construction 3 — SP-024, three conjuncts under one identity.** "Canonical history order is ascending DaySlot ordinal, then ascending successful-record order within the active interval associated with that DaySlot. **Equal content never collapses distinct positions.**" An embodiment that reverses within-interval order and an embodiment that mis-sorts across DaySlot ordinals both fail SP-024 and only SP-024 at the element where their limitation bites.

**Conclusion.** The individuation is exactly as fine as the clause granularity, and the clause granularity is the author's. The repair moved naming authority from the embodiment to the author — which is a genuine improvement, because the author is not the party being measured — but **it did not move it to the source**, and it did not make the individuation adequate to the distinctions P-L1-A seals. `INV-RC-KERNEL-4` cannot supply the missing calibration: it is a constraint against redundancy among admitted constructs, and it has nothing to say about a single construct carrying several meanings.

### 3.2 Converse test — over-distinction

Two embodiments with the *identical* substrate limitation can lawfully publish different sets, because SP-022 and SP-032 encode overlapping obligations (both require that a successful `record` produce one ordered pending contribution) and no clause states whether an embodiment that fails the stronger also "cannot honor" the weaker. `{SP-022}` and `{SP-022, SP-032}` are both defensible for G′; SP-152 would report divergence between two substrates that differ in nothing.

Read literally against the requirement set, `INV-RC-KERNEL-4` condemns this: SP-022 and SP-032 "collapse to one meaning," and by the invariant's own terms "encode neither." The invariant v0.5 invokes to guarantee injectivity, applied to the set the repair depends on, falsifies part of that set.

**Both failure modes are present.** Neither is safe, and the mandate's threshold line `loss identity collision — NONE within RC-0001 semantics` is **not met**.
