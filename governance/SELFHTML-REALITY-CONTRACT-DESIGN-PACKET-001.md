## 3. The load-bearing object

## 4. Semantic repair — intention ≠ established outcome

`offer: transforms: visitor` is too strong: the system does not *know* the offer transforms the visitor. Relationships carry **two axes**:

```
SEMANTIC RELATION  (SUPPORTS · CONTEXTUALIZES · ENABLES · INTENDS_TRANSITION · …)
EPISTEMIC STANDING (e.g. VERIFIED · DECLARED · INFERRED)
```

Example: `proof SUPPORTS authority, standing VERIFIED` vs `offer INTENDS_TRANSITION recognition→initiation, standing DECLARED`. Conversion language may not become fake causality.

## 5. State machine — system state ≠ visitor inference

Observable events (`page_entered`, `cta_clicked`, `form_submitted`…) are one class; inferred states (`recognition`, `desire`, `trust`) are another. Inferred states carry their evidence basis and `standing: INFERRED`. Analytics does not read minds.

## 6. SELFponents are capability realizers

Not `HeroComponent`/`PricingComponent` but `AuthorityRevealer`, `ProofSurface`, `DistinctionEngine`, `NarrativeBridge`, `TrustWitness`, `InitiationSurface`. The compiler resolves `Capability → PrimitiveSet`; DOM structure (`<section>`, `<article>`, …) is downstream.

## 7. HBCSELF's clarified role

HBC is **not** the page generator. It is the proof membrane around the new compiler: `Reality Contract → SELFHTML Compiler → Artifact → HBC-derived validate/witness/differentiate/prove`. Differentiate upgrades from phenotype distance to the typed delta already ratified in the adoption doctrine §6: `Δ = (Δ_semantic, Δ_structural, Δ_visual, Δ_responsive, Δ_interaction, Δ_authority, Δ_evidence)` — no universal green check; each axis carries its own status and findings.

## 8. Proof is obligation-driven

The compiler never awards `witnessed` for having emitted something. Chain: `Capability → Proof Obligation → Required Observation → Evidence → Adjudication`. Proof obligations name their claim, requirements, required evidence classes (source/dom/render, each individually required or not), and a closed verdict set. Inherited HBC law: **if the required observation cannot be made, say `NOT_WITNESSED`. Never "probably fine."**

## 9. The intellectual property is the contract lineage, not the artifact

The artifact is disposable; the regenerable source-of-truth package is: RealityContract + Semantic Graph + Primitive Registry version + Compiler version + Authority Contract + Evidence bindings. Every manifestation binds `contract_digest`, `ontology_version`, `primitive_registry`, `compiler_version`, `artifact_digest` — the same YAML under two compiler/primitive versions may produce radically different realities, so regeneration must be reproducible.

## 10. Four contracts, not one overloaded file

```
ManifestationSpec = R + A + E + D
```

1. **RealityContract** — what reality is desired (identity, intention, states, capabilities, relationships, transitions, constraints).

3. **EvidenceContract** — what must be witnessed (claims, proof sources, render/interaction/runtime observations).
4. **DifferentiationContract** — what sameness must be resisted (category norms, generic structures, competitor resemblance, identity dilution).
