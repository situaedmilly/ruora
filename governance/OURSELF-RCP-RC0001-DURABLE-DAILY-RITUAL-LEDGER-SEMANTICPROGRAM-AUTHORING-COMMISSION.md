## 2. Movement identity and target output

### 2.1 SemanticProgram, for this commission

A SemanticProgram is the substrate-independent statement of the reality that must remain the same across embodiments. It specifies meaning, lawful state changes, observable consequence, and authority expectations without choosing the mechanism that implements them.

It is not:

- a database schema;
- a UI flow or visual design;
- an API contract;
- a storage-engine selection;
- a web/iOS feature parity checklist;
- a RealityIR encoding;
- a normalized observation vocabulary;
- a conformance vector;
- an implementation backlog.

### 2.2 Authoring question

> What does the Durable Daily Ritual Ledger mean, independently of any substrate, strongly enough that two embodiments can be shown to preserve or violate that meaning?

The candidate must make falsification possible. A clause that cannot distinguish a preserving embodiment from a meaning-changing embodiment is descriptive context, not yet a semantic requirement.

### 2.3 Authorized target path

The authoring movement may create exactly one candidate artifact:

```
governance/OURSELF-RCP-RC0001-DURABLE-DAILY-RITUAL-LEDGER-SEMANTICPROGRAM-v0.1-CANDIDATE.md
```

No other file is authorized for mutation by this commission.

## 6. Required anatomy of the candidate

The candidate must contain each section below. Where the admitted sources do not determine an answer, the section remains present and carries `UNRESOLVED`; silence is not an answer.

### 6.1 Identity, purpose, and non-goals

Specify what reality the program governs, who it is for, what outcome it preserves, and which adjacent meanings are explicitly outside the subject.

### 6.2 Semantic actors and authority roles

Identify every actor that may initiate, observe, confirm, refuse, amend, or invalidate an event. Observation and authority must be modeled separately; ability to see a fact does not imply power to confirm it.

### 6.3 Semantic facts and identity

Define the facts the ledger can carry, their identity conditions, and which distinctions make two facts semantically different. Do not choose serialization or storage fields.

### 6.4 Operations

For every operation, specify:

```
intent
preconditions
successful outcome
refusal conditions and refusal outcome
whether an attempted operation has semantic presence
whether an intermediate state is meaningful, forbidden, or unobservable
which facts change and which must not change
```

### 6.5 State model and invariants

Define lawful states, lawful transitions, terminal or reversible states, and invariants that every embodiment must preserve. If correction, amendment, deletion, supersession, or invalidation exists, its meaning must be explicit rather than inferred from a storage metaphor.

### 6.6 Discontinuities

Enumerate the interruptions the subject’s semantics contemplate. For each one, specify what must survive, what must not survive, what order must remain, and what degradation is permitted.

No discontinuity may be added merely because the current F-05 vocabulary can express it. No required discontinuity may be omitted because a present emitter cannot survive it.

### 6.7 Observer and confidentiality semantics

Specify who must be able to observe each fact, who must not, when observers must agree, and whether partial or delayed visibility changes meaning. A public fact, a shared fact, and an authority-confirmed fact are not interchangeable unless the candidate explicitly makes them so and states why.

### 6.8 Authority and confirmation semantics

Specify which states count without confirmation, which require confirmation, who can confer it, whether it can be revoked, and whether recorded intent must remain distinguishable from accepted fact.

### 6.9 Time, day, ordering, and recurrence semantics

Specify whether time is semantic; what constitutes a “day”; how ordering is determined; how concurrent, late, repeated, missed, or corrected acts behave; and whether recurrence creates new identity or continues an existing one.

Wall-clock timestamps may not silently serve as a total-order oracle. If time matters, it must be part of the intended meaning.

### 6.10 Failure, duplication, and conflict semantics

Specify the meaning of refusal, retry, duplicate intent, partial outcome, conflict, and recovery. This is semantic behavior, not an instruction to choose transactions, queues, or consensus machinery.

### 6.11 Falsifying traces

Provide minimal substrate-independent traces that include:

- one successful operation;
- one refused operation;
- one contemplated discontinuity;
- one observer disagreement or visibility boundary, if the program permits either;
- one authority boundary;
- one temporal, duplicate, or conflict edge case;
- one pair of outcomes that look similar operationally but differ semantically.

Each trace must state what observation would falsify preservation of the intended meaning.

### 6.12 Founder decision docket

Every `UNRESOLVED` item must be gathered into one docket with:

```
decision id
exact question
available alternatives
semantic consequence of each alternative
downstream RC-0001 consequence, if known
author recommendation, if any, labeled AUTHOR-PROPOSED
status = FOUNDER_DECISION_REQUIRED
```

The author may frame a decision. The author may not manufacture its ratification.

## 8. Anti-back-solving law

The SemanticProgram is the question against which the representation will later be judged. It may not be authored to produce a preferred answer.

```
FORBIDDEN   selecting semantics because Option A can express them
FORBIDDEN   adding semantics because Option C would then be compelled
FORBIDDEN   calling a distinction diagnostic because the ladder lacks a name
FORBIDDEN   calling a distinction load-bearing because a candidate vocabulary
            already exposes it
FORBIDDEN   weakening meaning to fit HBC or strengthening meaning to defeat HBC
FORBIDDEN   importing LOCAL, CANONICAL, or another borrowed term without a
            subject-local definition and namespace-collision check
```

The candidate’s normative sections should not mention Options A, B, or C. If representation lineage must be disclosed, it belongs only in the provenance statement, not in the rationale for a semantic choice.
